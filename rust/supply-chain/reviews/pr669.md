## RSA is a deliberately narrow review

`rsa 0.9.10` documents the Marvin private-key timing vulnerability, [RUSTSEC-2023-0071](https://rustsec.org/advisories/RUSTSEC-2023-0071.html). This change does not grant it the built-in `safe-to-deploy` criterion.

The custom `rsa-public-key-encryption` criterion, which does **not** imply safe-to-deploy, covers the reviewed public-key construction/decoding and padded encryption used by the Steam wrappers. The package separately receives safe-to-run coverage. Steam builds an RSA public key from the authenticated server response or an embedded public key, reads public components during its build, and encrypts password/session-key bytes. It holds no RSA private key and performs no private-key signing, generation or decryption. The unused public signature-verification helper is not a private-key operation.

Only the two reviewed Steam integration packages may consume RSA. Their dependency criteria require both the custom criterion and safe-to-run; the RSA package policy still requires safe-to-deploy for every primitive dependency. Changing consumers, source, features or usage requires a new review. The scoped review is not transferable to an application using RSA private keys.

## Required scope and source guards

The implementation is in [check-reviewed-dependencies](../../../.github/scripts/check-reviewed-dependencies), its [resolved graph policy](dependency-scope.json), and [source-analysis guard](guard.rs). [test-reviewed-dependencies](../../../.github/scripts/test-reviewed-dependencies) runs the guard and vendor regressions. The [source inventory](vendor-files.json) pins all 290 files in ten local dependencies; all 17 positive/negative guard tests pass. Merely putting a dependency behind a path patch or disabling `audit-as-crates-io` is insufficient; the guard enforces the following:

1. Verify an exact checksum snapshot of every vendored package and every source consumer on which a narrow audit relies. Preserve original archive SHA-256/provenance separately from patched-source identity. Changes to reviewed source must fail until re-reviewed and the snapshot is intentionally updated.
2. Inspect the resolved Cargo graph, including enabled features and inverse dependencies, rather than only declared manifest versions. Constrain RSA to the reviewed public-key consumers; crossbeam-utils to CachePadded consumers; and directory/Redox/jobserver dependencies to their reviewed paths. Validate the source use as well as the parent names.
3. Keep TOML `unsafe` and `unbounded` features disabled. Preserve the reviewed TOTP, spin and platform feature sets. Redox account authentication/admin and optional low-level libredox APIs are not approved for use; they remain outside the supported Linux runtime.
4. Check supported build/deployment targets and retain the Linux build-context assumptions for jobserver. MAKEFLAGS, inherited descriptors, Cargo/Rust compiler executables and HOME/XDG configuration are trusted operator/build inputs, not values accepted from remote users.
5. Retain the existing [no-new-exemptions gate](../../../.github/scripts/check-cargo-vet-exemptions), run locked cargo-vet against the resolved graph, and run vendor regressions plus normal workspace formatting/lint/tests. A snapshot checker must also have a negative test proving that source or feature drift is rejected.

Known excluded behavior is intentional and visible: the unused UserDirs parser can panic on malformed trusted configuration; Redox account writers/login helpers have policy and serialization caveats; crossbeam AtomicCell has a memory-model concern; jobserver's generic configure API requires descriptor-owner lifetime discipline. These are not claimed safe for arbitrary new callers. The guards reject source, feature and consumer changes that could silently expand this limited evidence.

Reproduce the CI gates from the repository root:

```sh
.github/scripts/check-reviewed-dependencies
cargo vet check --locked --manifest-path rust/Cargo.toml
.github/scripts/test-reviewed-dependencies
cargo fmt --manifest-path rust/Cargo.toml --all -- --check
cargo clippy --locked --manifest-path rust/Cargo.toml --workspace --all-targets --all-features -- -D warnings
cargo test --locked --manifest-path rust/Cargo.toml --workspace --all-targets --all-features
```

A dependency/source/feature/configuration update intentionally requires renewed review and updated manifests. A passing checksum alone is not fresh source-review evidence.
